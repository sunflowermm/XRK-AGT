## 何时使用

- 「把这份报告改成邮件」「周报抽成 PPT」「一篇文章发多平台」
- 同一份材料要 **不同长度 / 不同受众 / 不同渠道** 的多版本
- 活动、发版、政策变更后需要**统一口径**的多形态输出
- 长文档定稿后的**二次传播**打包（不重新调研）

## 动手前

1. **`read` 原文**（工作区路径或用户粘贴）；大文用 `grep` 定位决策、数字、待办
2. 确认：**事实源**是哪一份（以最新、最权威为准）、**对外还是对内**、要几种衍生格式
3. 列出**不可删**项：日期、数字、决策结论、负责人、截止时间、风险提示
4. 扫 **`ENV.md`**：要 docx/pptx 时知悉降级路径（Markdown 大纲仍可先交付）

## 原则

- **单一事实源**：不新增原文未证实的信息；各版本数据、日期、人名必须一致
- **内容金字塔**：长文为根，越短越删形容词，越保留数字与决策
- **分版本标注场景**：每段注明「适用：全员邮件 / 对外短讯 / 领导 1 页」
- **敏感分级**：内部细节不进对外短讯；未公开数字用 `[待确认]` 或删除
- **先结构后润色**：先出各版本骨架，再交 office-copy / office-proofread 精修

## 内容金字塔

```
长文（报告 / 纪要 / 方案 / 调研）
  ├─ 领导 briefing（1 页）     → office-briefing
  ├─ 邮件摘要（主题 + 200 字）  → office-email
  ├─ PPT 大纲（8–12 页 bullet） → office-pptx
  ├─ 群公告（≤100 字）          → office-internal
  ├─ FAQ（3–5 问）              → office-faq
  ├─ 短讯 / 通稿要点            → office-press
  └─ Changelog 用户向条目       → office-changelog
```

## 输出模板

```markdown
# 一稿多用：[原文标题]
> 事实源：[路径或文件名] | 衍生日期：YYYY-MM-DD

## 原文要点（不可删）
1. …（含数字/日期/决策）
2. …
3. …

## 版本 A：邮件
**适用**：对内全员 / 跨部门
**主题**：…
**正文**：…

## 版本 B：PPT 大纲
**适用**：周会汇报
| 页 | 标题 | 要点（bullet） |
|----|------|----------------|
| 1 | 封面 | … |
| 2 | 结论 | … |

## 版本 C：群公告（≤100 字）
…

## 版本 D：FAQ 种子（可选）
- Q：… → A：…

## 一致性自检
- [ ] 各版本数字、日期一致
- [ ] 对外版无内部敏感信息
- [ ] 待办负责人、截止日期一致
```

## 工具用法（工作区）

| 操作 | 工具 |
|------|------|
| 读原文 | `read`；`docs/<项目>/` 下分章则合并读或按章衍生 |
| 新建衍生包 | `write` → `docs/repurpose/<主题>-derivatives.md` |
| 更新某一版本 | `read` → **`search_replace`** 改对应「版本 X」节 |
| 从纪要抽待办 | `grep`「待办|action|TODO」→ 填入各版本 |

勿对已有定稿原文做未经确认的 `search_replace`；衍生稿写新文件或独立节。

## 流程清单

- [ ] 提取 3–7 条「不可删」要点
- [ ] 按用户要的格式数生成版本（缺省：邮件 + 公告 + briefing 要点）
- [ ] 做一致性自检表
- [ ] 写入工作区并回报路径
- [ ] 聊天：各版本前 2 行预览 + 完整文件路径

## 缩短技巧

| 保留 | 删除 |
|------|------|
| 数字、单位、口径 | 背景铺垫、形容词 |
| 决策与待办（谁/何时） | 过程细节、重复论证 |
| 风险一句 + 缓解 | 冗长案例（改「见附件」） |

## 禁止

- 不同版本间数据、日期、结论矛盾
- 把内部敏感信息写进对外短讯、群公告
- 借「一稿多用」名义补充未证实的「好消息」
- 未读原文就写衍生版
- 整文件 `write` 覆盖用户正在协作的多人稿
