## 何时使用

- 用户说「根据这份材料写 FAQ」「整理常见问题」「客服标准答复」「帮助中心条目」
- 产品/制度/流程变更后，要把旧文档改写成问答体
- 群聊、工单里反复出现的问题需要沉淀成可复用话术库
- 要把内部说明改写成**对外用户可读**的 FAQ（需脱敏）

## 动手前

1. 扫一眼工作区 **`ENV.md`**；源材料在工作区则用 `list_files` → `grep` 定位 → `read`
2. 确认：**受众**（终端用户 / 内部员工 / 客服）、**渠道**（帮助页 / 机器人 / 邮件嵌入）、**语言**（默认中文）
3. 收集单一事实源：用户粘贴、工作区 `docs/` 文件、会议纪要、已有 FAQ 草稿
4. 若材料不足以回答某类问题，列入「待产品确认」，**不编造**政策、价格、 SLA

## 原则

- **用户原话式提问**：Q 用真实会问的句式，避免内部术语当头
- **双轨答案**：短答 ≤80 字（搜索/卡片/机器人）；长答给步骤与背景（帮助页）
- **聚类去重**：相似问题合并；同一政策只保留一条权威答
- **第二人称「你」**；步骤用编号；警告、例外用 **注意** 单独成段
- **内外有别**：对外 FAQ 去掉内部代号、未公开路线图；内部 FAQ 可保留工单链接格式
- **可追溯**：每条附「相关链接/文档」或源材料章节引用

## 工具用法（工作区）

| 步骤 | 工具 |
|------|------|
| 找源材料 | `list_files`（`docs/`、`exports/`）→ `grep` 关键词 |
| 读章节 | `read`；大文件分段读 |
| 新建 FAQ | `write` → `docs/faq/<主题>.md` |
| 改已有 FAQ | 先 `read` → **`search_replace`** 精确替换条目或追加 Q 块 |
| 批量替换术语 | `grep` 定位 → 多次 `search_replace`（勿整文件 `write` 覆盖） |

产出默认放 **`docs/faq/`** 或用户指定路径；需对外 docx 时交 **office-docx**。

## 流程清单

- [ ] 读完全部源材料，列出问题候选（≥用户预期条数时再聚类）
- [ ] 合并重复问法，统一术语（同一概念一词）
- [ ] 每条：短答 + 长答 + 链接/出处
- [ ] 标注「待产品确认」与开放问题
- [ ] 对外版：脱敏、删内部代号
- [ ] 写入工作区文件并回报路径；聊天里给摘要 + 前 3 条示例

## 禁止

- 不编造政策、价格、退款规则、 SLA、未公布的排期
- 不把未核实猜测写成确定答复
- 不对外 FAQ 泄露内部架构、未公开客户名、员工私人信息
- 不为小改动用 `write` 整文件覆盖已有 FAQ
- 不读写工作区外敏感路径（`.env`、密钥）
