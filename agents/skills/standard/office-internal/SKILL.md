## 何时使用

- 对内：**周报、3P、项目状态、事故通报、部门通知、领导一页纸**
- 「同步一下进展」「写个事故报告」「全员通知」「内部 FAQ 批量回」
- 群机器人/飞书/企微长文需要**可扫读**结构（非对外邮件口吻）
- 与 **office-email** 分工：跨公司、客户、正式邮件 → office-email；结构化内部同步 → 本技能

## 动手前

1. 确认：**受众**（本组/全部门/全员）、**渠道**（文档/群公告/邮件正文）、**周期**（周报日期）
2. **`read` 工作区**既有周报、项目 STATUS、事故时间线草稿
3. 数字、日期、里程碑状态**可验证**；未知标 `[待确认]`，不猜进度百分比
4. 事故类：先对齐**影响范围**与**是否需对外口径**（对外另段或交 office-press）

## 原则

- **结论前置**：第一段说「正常/有风险/已恢复」
- **3P 清晰**：Progress / Plans / Problems 不混写
- **阻塞要人**：Problems 里写「需要谁协助、什么决定」
- **状态灯 honest**：🟢正常 / 🟡风险 / 🔴阻塞；不全员绿灯掩盖问题
- **事故写时间线**：发现→定位→缓解→恢复，UTC+8 或注明时区
- **内部可稍直接**：少敬语，多事实与 action

## 工具用法（工作区）

| 操作 | 工具 |
|------|------|
| 续写周报 | `read` 上周 `docs/weekly/…` → **`search_replace`** 更新三节 |
| 新建 | `write` → `docs/weekly/` 或 `docs/internal/` |
| 从事故日志抽时间线 | `grep` 时间戳 → 填入表格 |
| 转邮件发送 | 结构不变，套 **office-email** 主题/称呼 |

## 流程清单

- [ ] 选模板（3P / 项目 / 事故 / 通知）
- [ ] 填状态灯与可验证交付
- [ ] Problems 含协助人与决策项
- [ ] 事故：时间线 + 行动项表
- [ ] 写入工作区；聊天给状态一句话 + 路径

## 语气参考

| 对象 | 语气 |
|------|------|
| 直属团队 | 简洁、可带技术细节 |
| 全部门/全员 | 少术语、多链接 |
| 领导摘要 | 压缩为 **office-briefing** 或周报顶部 5 行 |

## 禁止

- 不隐瞒 🔴 阻塞（应早暴露 + 写协助人）
- 不编造恢复时间、影响人数
- 事故报告不甩锅具名个人（用角色/系统）
- 不把未核实猜测写进「根因」
- 内部通知不夹带对外未公开数据
