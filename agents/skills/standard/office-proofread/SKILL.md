description: 定稿前结构化审校：七遍扫（结构、清晰、术语、重复、读感、语法、事实）；输出修订摘要、修订稿与待作者确认项；比 office-copy 更深，适合领导材料与对外文案

## 何时使用

- 定稿前润色、领导材料、对外文案、投标/方案语言审查（**非法律意见**）
- 用户说「帮我过一遍」「审校」「检查有没有问题」「定稿前最后一遍」
- 长文各章写完后做**全文一致性**与**事实核对**
- office-copy 轻量润色仍不够：需要结构化清单与 `[原]→[改]` 对照

## 动手前

1. 确认交付形式：**修订稿 + 摘要** / **仅 clean 终稿** / **对照版**（重大改动）
2. **`read` 全文**；长文分章 `read` 并对照 `docs/<项目>/STATUS.md`（若有）
3. 向用户索要或在工作区找：**事实源**（数据表、纪要、上级批复）用于第 7 遍
4. 明确禁区：不可改商业承诺、合同条款含义、已签字数字

## 原则

- **先结构后字句**：顺序不对，改句子的收益低
- **术语一致**：同一概念一词；缩写首次展开（对外材料）
- **事实不猜**：数字、日期、人名与源材料不一致 → 列入「待作者确认」，不擅自改
- **改动可解释**：摘要里说明「为什么改」，便于作者拍板
- **尊重作者立场**：润色语气，不改变承诺、结论方向、责任归属

## 七遍扫（按需跳过）

| 遍 | 检查项 | 典型动作 |
|----|--------|----------|
| 1 结构 | 段落顺序、小标题、结论是否前置 | 整段上移/补过渡句 |
| 2 清晰 | 长句拆分、指代明确、删套话 | 一句一意 |
| 3 术语 | 同一概念一词；缩写 | 建 mini 术语表 |
| 4 重复 | 同段/跨段重复论点 | 合并，留最强表述 |
| 5 读感 | 朗读不顺；被动改主动（适度） | 改连接词 |
| 6 语法 | 标点、的地得、中英空格、专名 | 统一格式 |
| 7 事实 | 数字、日期、人名、引用 | 对照源材料 |

## 输出格式

```markdown
## 修订摘要（≤5 条）
1. 结构：…
2. 术语：统一「…」为「…」
3. 事实：第 X 段日期与源材料不一致 → 待确认

## 修订稿
（全文或用户指定章节）

## 待作者确认
- [ ] 第 3 节「2026-Q1 营收」：原文 1200 万，材料为 1180 万，请确认口径
- [ ] 「合作伙伴 A」是否可对外具名

## 术语表（可选）
| 原表述 | 统一为 |
|--------|--------|
| … | … |
```

**对照模式**（用户要求时）：重大句段标 `[原] …` → `[改] …`；clean 版则只给终稿。

## 与 office-copy 分工

| | office-copy | office-proofread |
|---|-------------|------------------|
| 深度 | 轻量、单次改写 | 多轮、结构化 |
| 场景 | 邮件、短讯 | 长文、对外、领导材料 |
| 输出 | 改写文 + 3 条说明 | 摘要 + 终稿 + 确认清单 |

## 工具用法（工作区）

| 操作 | 工具 |
|------|------|
| 读稿 | `read`；超长用 `grep` 查术语、数字 |
| 写回修订稿 | 用户确认后：`search_replace` 逐段替换；**勿未确认就改源文件** |
| 新建审校记录 | `write` → `docs/review/<文件名>-proofread.md`（摘要+待确认） |
| 长文档分章 | 每章 `search_replace` 单独提交；合并前做术语 `grep` |

默认：**审校结果写新文件或聊天交付**；改用户原稿须说明并获同意。

## 流程清单

- [ ] 通读一遍，标记结构问题
- [ ] 按七遍扫执行（可合并相邻遍）
- [ ] 生成修订摘要与待确认项
- [ ] 交付修订稿（或对照版）
- [ ] 用户确认事实项后再 `search_replace` 回源文件

## 禁止

- 不改变商业承诺、合同责任、审批结论的**含义**
- 不提供法律合规、税务、劳动仲裁等专业结论
- 不捏造「更正后」的数据；不确定就标注
- 不经确认直接覆盖用户唯一原稿
- 把敏感修订内容写入 `memory/`（除非用户要求且已脱敏）
