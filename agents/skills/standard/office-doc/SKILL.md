## 何时使用

- 写**报告、方案、立项说明、工作汇报、制度草案、公告、说明书**
- 用户要「正式一点」「公文风」「能贴进 Word 的结构」
- 尚未要求 .docx，或环境仅 A 档（Markdown 即为交付）
- 内部材料需要**固定章节**（背景→问题→方案→资源→风险→结论）

## 动手前

1. 确认：**文档类型**（汇报/方案/通知）、**读者**、**篇幅**、**是否要请示/批复事项**
2. 扫 **`ENV.md`**：用户要 Word 时，知悉 **office-docx** / pandoc 路径或「粘贴转换」降级
3. 工作区已有模板或旧版：`list_files` → `read` → 用 **`search_replace`** 增改章节
4. 收集：数据出处、附件清单、联系人——缺则 `[待补]`

## 原则

- **结论/事由前置**：汇报类先写结论与建议；通知类先写事由
- **层级不跳级**：`#` → `##` → `###`；便于 Word 样式映射
- **数据表格化、步骤编号化**：少用大段 prose 堆数字
- **请示事项单独成节**：领导一眼看到「请批示…」
- **附件清单**：正文引用「见附件 1」则文末列清单
- **不虚构**：政策条文、审批结果、预算批复

## 常用结构

### 汇报 / 报告

1. 摘要（可选，≤200 字）
2. 背景与目标
3. 现状与问题（可含数据表）
4. 方案 / 建议（分点，推荐方案标 ★）
5. 资源与时间（人力、预算、里程碑）
6. 风险与对策
7. 结论与请示事项
8. 附件清单

### 方案 / 提案

1. 痛点与机会
2. 目标与范围（**含不做什么**）
3. 方案对比（表格）
4. 实施步骤与里程碑
5. 预算 / 人力粗算（有数据才写）
6. 成功标准（可验收指标）

### 通知 / 公告

1. 事由（一句话）
2. 具体安排（时间、地点、对象、方式）
3. 注意事项（**注意** 单独条）
4. 联系人及方式
5. 生效/废止说明（制度类）

## 格式规范

```markdown
# 文档标题

**发文/汇报单位**：… | **日期**：YYYY-MM-DD | **密级**：（如有）

## 一、……

正文。数据示例：

| 项目 | 数值 | 备注 |
|------|------|------|
| … | … | … |

1. 第一步 …
2. 第二步 …

**注意**：……

## 附件清单
- 附件 1：……
```

- 中英文混排：英文/数字与中文间加空格（适度）
- 专有名词首次全称，括号缩写

## 工具用法（工作区）

| 操作 | 工具 |
|------|------|
| 新建文档 | `write` → `docs/<主题>.md` |
| 改章节 | `read` → **`search_replace`**（按节替换，勿整篇覆盖） |
| 合并多节 | 长项目见 **office-long-doc**（`docs/<项目>/ch-NN.md`） |
| 转 Word | **office-docx** 或 pandoc（C 档 run）；否则说明手动粘贴 |

产出放 **`docs/`**；对外定稿前可走 **office-proofread**。

## 禁止

- 不虚构政策条文、审批结果、红头文号
- 不代填真实签名、公章说明
- 不为小改 `write` 覆盖整篇已定稿
- 不把内部未定方案写成已批准
