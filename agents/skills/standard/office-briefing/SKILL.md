## 何时使用

- 「给老板一页纸」「决策 memo」「电梯汇报」「董事会摘要」「要不要投/要不要做」
- 材料很长但决策者**只有 3–5 分钟**阅读时间
- 会议前需要**明确拍板项**：选 A 还是 B、预算批多少、截止日何时
- 从调研/方案/纪要压缩成**可决策**格式（不是信息堆砌）

## 动手前

1. **`read` 源材料**（报告、数据、纪要）；`grep` 抓数字、选项、反对意见
2. 向用户确认：**决策问题**一句话是什么、**截止日**、**读者**（CEO/部门负责人/投委会）
3. 缺数据时标注 `[待补]`，不编造 ROI、市场规模
4. 附件细节放工作区 `docs/briefing/`，正文只链路径

## 原则

- **结论第一**：标题下即「建议 + 需否决策」；老板不翻页也能懂
- **选项可比**：每个选项写清优点、缺点、成本/时间、不可逆性
- **数字带口径**：单位、统计周期、样本范围；口径不明则标注
- **风险诚实**：写缓解措施，不写「无风险」
- **下一步可执行**：批准后的 action 含负责人与日期
- **一页优先**：正文控制在 1–2 屏；细节放附件

## 工具用法（工作区）

| 操作 | 工具 |
|------|------|
| 读长报告 | `read` / 分章 `read`；`grep`「建议|方案|预算」 |
| 新建 briefing | `write` → `docs/briefing/<主题>.md` |
| 更新数字 | `read` → **`search_replace`** 改表格行 |
| 插图 | 数据图交 **office-chart**；briefing 只留一句解读 + 链路径 |

## 流程清单

- [ ] 用一句话写出「决策问题」
- [ ] 写结论 + 建议（先于背景）
- [ ] 列 ≥2 个真实选项（含「不做」若合理）
- [ ] 风险与未决项不藏段尾
- [ ] 下一步表可抄进日历/待办
- [ ] 写入工作区；聊天给「结论 + 需决策」两段

## 常见失误

| 失误 | 改法 |
|------|------|
| 背景占 80% | 背景 ≤5 bullet，细节附件 |
| 只有推荐无对比 | 至少 A/B，说明为何不选 A |
| 数字无单位 | 补单位、周期、来源 |
| 无截止日 | 明确「需在 X 日前决策否则 …」 |

## 禁止

- 不虚构财务预测、竞品数据、领导已表态
- 不把未讨论方案写成「共识」
- 不省略「需决策」让读者猜
- 不在 briefing 里堆 5000 字（应拆 **office-long-doc**）
